# Personal memory is separate from ceremony history

Issues #22 and #23 distinguish durable operational Ceremony records from optional, expiring
Personal Topic Notes. Personal memory defaults off; activation is the server administrator's
choice, not individual consent. Individual consent onboarding is deferred, while disclosure,
private inspection, exclusion, opt-out and forgetting controls are required at introduction.

Notes retain only short ordinary-topic facts from delivered exchanges. Stable attribution and
access boundaries are enforced in code; semantic ownership and sensitivity remain fallible model
judgments, with conservative omission. Recall cannot renew retention. Forgetting removes live
notes but not operational records, SQLite remnants or operator backups.

Capture provenance limits later recall. Initial category sharing uses exact viewing-policy
equality for ordinary text channels and rejects uncertain access; public threads remain source
contained and private threads are omitted. Moving a source cannot broaden existing notes. This
deliberately loses recall opportunities rather than treating bot access as proof of a shared audience.

Durable member generations and capture cutoffs prevent stale work or fetched old statements from
undoing deletion. Delivery rechecks permissions and local invalidation before invoking Discord;
an already-submitted message lies outside that boundary. Extraction shares the foreground provider's
rate limit and is cancellable, bounded, and dispensable rather than a durable queue of transcripts.
